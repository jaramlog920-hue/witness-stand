# 《증언대: 신약 재판소》 스펙 v0.1

관련 문서: [exclusion-list.md](exclusion-list.md) (최상위 기준) · [case-candidates.md](case-candidates.md) (사건 후보) · [content-audit.md](content-audit.md) (전수 검수 기록)

## 1. 한 줄 정의

플레이어는 **조사관**이다. 초대교회 시대 소문 게시판에 올라온 주장을 **신약 본문에서 근거를 찾아** 판정하고, 여러 인물의 증언을 대조해 사건 기록을 완성한다. 통독 게임이 아니라 **이해도 게임**이다.

## 2. 목표 / 비목표

**목표**
- 서신서가 "누구의 어떤 주장에 대한 반박인지" 몸으로 알게 한다.
- 같은 사건을 다른 인물의 관점에서 다시 보게 한다.
- 모든 결론이 **본문 전문**으로 끝난다. 정확도는 스크립트로 기계 검증한다.

**비목표**
- 260장 통독 추적 (→ 복음의 전령)
- 암기·암송 (→ 복음의 전령 미션)
- 교리 교육, 교단 입장 설명
- 소셜·랭킹·계정. 로컬 저장만.

## 3. 세계관·톤

- 시대: 1세기. 플레이어의 직책은 **데오빌로의 조사관**이다.
  - 근거: 눅 1:1-4 — 누가는 "근원부터 자세히 미루어 살펴" 데오빌로 각하에게 기록을 써 보냈고, 그 목적은 "배운 바의 확실함을 알게 하려 함"이다. 플레이어는 데오빌로가 그 기록을 확인하도록 보낸 사람이다.
  - 이 직책의 장점: 조사 대상이 항상 "세간의 소문과 사람들의 증언"이지 예수님이 아니다. 로마 관리·산헤드린처럼 예수님을 심문하는 자리가 아니라, **기록이 맞는지 확인해서 각하에게 보고하는** 자리다.
  - UI: 첫 화면에 데오빌로의 위임장(눅 1:3-4 전문 인용) → 조사관 이름 입력(선택) → 게시판. 결과 화면의 인장은 "조사관 ○○○ 확인".
  - 등급 명칭도 이 프레임: 견습 → 서기 → 조사관 → 선임 조사관 → 데오빌로의 기록관.
- UI 용어: **소문** (가짜뉴스 ✕), **사건 파일**, **증거**, **판정**, **기록 보관소**. "재판소"는 앱 이름에만.
- 비주얼: 양피지·잉크·밀랍 인장. 어둡고 차분한 조사실 톤. 예수님 얼굴 이미지 없음.
- 실패 없음. 틀리면 본문으로 돌아가서 다시.

## 4. 게임 루프

### 4-1. 소문 사건 (핵심 루프, 80건)

```
게시판 ─▶ 사건 파일 ─▶ 조사(본문 읽기 + 증거 표시) ─▶ 판정 ─▶ 결과 ─▶ 보관소
```

1. **게시판** — 미해결 소문이 쪽지 형태로 붙어 있다. 각 쪽지: 소문 한 줄 + 출처(본문 표현 그대로) + 난이도 ●○○.
2. **사건 파일** — 쪽지를 열면 소문 전문과 **조사 범위**(본문 구간 1~4개, 예: `마 28:1-15`, `마 27:62-66`)가 나온다.
3. **조사** — 조사 범위의 본문을 앱 안에서 읽는다. 절을 탭하면 **증거 표시**(최대 3절). 어떤 절이 정답인지는 안 보인다.
4. **판정** — 4택: `사실` / `왜곡` / `거짓` / `본문에 없음`. 판정 이유 입력은 없다(자유 텍스트는 채점 불가).
5. **채점**
   - 판정 일치 **AND** 증거 절 중 하나 이상이 정답 절 집합(`evidence`)에 포함 → **해결**
   - 판정이 두 가지로 읽히는 사건은 `alsoAccept`에 적은 판정도 정답으로 인정한다(중복 답변). 결과 화면 하단에 "중복 답변: …" 한 줄로 알린다
   - 판정 일치, 증거 불일치 → "판정은 맞지만 이 절은 근거가 되지 않습니다" → 증거 다시 선택 (판정 유지)
   - 판정 불일치 → "본문을 다시 보세요" + 조사 범위 중 **정답 절이 있는 구간만** 남겨서 힌트 (2회 틀리면 정답 절 **1개**만 강조)
     - 좁힌 범위에는 반드시 표시할 수 있는 정답 절이 남아야 한다. `absent` 판정 사건은 정답 절이 없으므로 **좁히지 않는다**(좁히면 "본문에 없다"를 확인할 수 없다)
     - 안내 문구는 화면이 실제로 달라진 만큼만 말한다 (좁혔을 때만 "조사 범위를 좁혔습니다")
6. **결과 화면** — 판정 인장이 찍히고, 그 아래 **근거 구절 전문**(개역한글, 절 번호 포함)이 가장 크게 나온다. 마지막에 `해설` 2~3문장(본문이 말하는 범위 안에서만).
7. **보관소** — 해결된 사건이 사건철에 꽂힌다.

`본문에 없음` 판정의 특수 처리: 증거 절 선택을 요구하지 않는다. 대신 조사 범위를 다 읽어야 판정 버튼이 활성화된다(스크롤 끝 도달).

### 4-2. 증언 사건 (고난도, 18건)

```
사건 개요 ─▶ 증언 카드 펼치기 ─▶ 질문별로 뒷받침 카드 연결 ─▶ 사건 기록 완성
```

1. **사건 개요** — 한 문단 + 본문 범위(예: `요 9:1-41`). 본문은 언제든 옆에서 읽을 수 있다.
2. **증언 카드** — 인물별 카드 4~6장. 카드 내용은 **본문 인용 그대로**(따옴표 + 절 번호). 인물이 여러 번 말하면 카드도 여러 장.
3. **질문** — 사건 기록의 빈칸 2~4개. 예:
   - "이 사람은 정말 날 때부터 소경이었는가?" → 뒷받침 카드: 이웃(9:8-9), 부모(9:20)
   - "누가 고쳤다고 하는가?" → 소경(9:11), 소경(9:25)
   - "바리새인들은 무엇을 문제 삼았는가?" → 바리새인(9:16)
   플레이어는 각 질문에 카드를 드래그(모바일: 탭-탭)로 붙인다. 필요한 카드 수는 표시한다("2장").
4. **채점** — 질문별로 정답 카드 집합과 일치해야 완성. 틀린 카드는 되돌아가며 "이 증언은 이 질문과 무관합니다".
5. **결과** — 완성된 사건 기록 + 본문 전문 링크 + 해설.

### 4-3. 진행·해금

- **사건철**(chapter) 단위로 묶는다:
  | 사건철 | 소재 | 해금 |
  |---|---|---|
  | Ⅰ 갈릴리와 예루살렘 | 복음서 소문 | 처음부터 |
  | Ⅱ 사도들의 길 | 사도행전 소문 | Ⅰ에서 8건 해결 |
  | Ⅲ 편지의 뒷면 | 서신서 소문 | Ⅱ에서 8건 해결 |
  | 증언대 | 증언 사건 18 | 해당 사건철의 소문 10건 해결 시 그 사건철 증언 사건 열림 |
- 사건철 안에서는 순서 자유. 난이도 ●○○부터 정렬해 보여준다.
- **조사관 등급**: 해결 수 기준 5단계(견습 → 서기 → 조사관 → 선임 → 기록관). 등급 자체는 아무것도 잠그지 않는다(장식).
- **완주**: 소문 80 + 증언 18 모두 해결 → 데오빌로에게 보내는 보고서 화면(보관소 전경) + "본문으로 돌아가기"(가장 많이 틀린 사건 3개의 본문 전문). 금테 전부 달성 시 보고서에 인장 하나 추가.

### 4-4. 보관소 (컬렉션)

- 사건철별 서랍. 해결한 사건은 판정 인장 색으로 표시(사실=청, 왜곡=황, 거짓=적, 본문에 없음=회).
- 필터: 판정별 / 책별 / 인물별(소문 주체·증언 인물).
- 사건을 다시 열면 결과 화면 재열람 + **[재조사]** 버튼.
  - 재조사: 증거 표시·판정을 초기화하고 조사 화면부터 다시. 힌트는 처음처럼 잠긴 상태로 시작.
  - 기록: `bestTries`(가장 적은 시도 수)와 `replays`(재조사 횟수)를 저장. 첫 해결 시 시도 수는 덮어쓰지 않는다.
  - 보관소 표시: 1회 만에 해결(판정·증거 모두 첫 시도) → 인장에 금테. 재조사로 달성해도 인정.
  - 증언 사건도 동일([재조사] → 카드 배치 초기화).

## 5. 데이터 구조

모든 콘텐츠는 `src/content/*.json`. 코드는 형식만 알고 내용은 모른다(전령과 동일 원칙).

```ts
// src/content/types.ts
type Verdict = 'fact' | 'twisted' | 'false' | 'absent'
type Ref = string                 // "마 28:11-15" — verify 스크립트와 동일 문법

interface RumorCase {
  id: string                      // "r001"
  chapter: 'I' | 'II' | 'III'
  difficulty: 1 | 2 | 3
  rumor: string                   // 소문 한 줄
  source: string                  // 주체, 본문 표현 그대로 ("대제사장들과 장로들")
  sourceRef?: Ref                 // 주체 표현이 나오는 절
  scope: Ref[]                    // 조사 범위 1~4개
  verdict: Verdict
  alsoAccept?: Verdict[]          // 중복 답변으로 인정할 판정. absent 와는 섞을 수 없다
  evidence: Ref[]                 // 정답 절 집합. absent면 []
  hintOrder: Ref[]                // 틀렸을 때 남길 구간 순서 (scope의 부분집합)
  alsoShow?: Ref[]                // 해설이 인용했지만 evidence 에는 없는 절. 결과 화면에서 함께 보여준다
  explanation: string             // 2~3문장. 따옴표 인용은 verify 대상
  recordedInText: boolean         // §2-1 표시 (성경이 직접 기록한 소문)
  flags?: ('review')[]            // ⚠ 검수 필요
}

interface Testimony {
  id: string                      // "t01-neighbors-1"
  speaker: string                 // 카드 표시 이름 ("이웃 사람들")
  speakerId: string               // 필터용 ("neighbors")
  quote: string                   // 본문 그대로
  ref: Ref
}

interface TestimonyQuestion {
  id: string
  prompt: string                  // "이 사람은 정말 날 때부터 소경이었는가?"
  answerCards: string[]           // Testimony.id 집합 (순서 무관, 전부 필요)
  record: string                  // 완성 시 사건 기록에 들어갈 문장
}

interface TestimonyCase {
  id: string                      // "w01"
  chapter: 'I' | 'II' | 'III'
  title: string
  summary: string
  scope: Ref[]
  cards: Testimony[]
  questions: TestimonyQuestion[]
  explanation: string
  flags?: ('review')[]
}
```

파일
- `src/content/nt-krv.json`, `books.json` — 전령에서 복사(빌드 스크립트 동일)
- `src/content/rumors.json` — `RumorCase[]`
- `src/content/testimonies.json` — `TestimonyCase[]`
- `src/content/chapters.json` — 사건철 메타(이름, 해금 조건, 순서)

## 6. 정확도 검증 (필수 게이트)

`scripts/verify-cases.mjs` — 전령의 `verify-missions.mjs`를 확장:

1. **참조 무결성**: 모든 `Ref`가 실재하는 책·장·절인가.
2. **인용 일치**: `Testimony.quote`는 `ref` 본문과 **공백 제거 후 완전 일치** (부분 인용 허용 안 함 — 증언 카드는 문장 단위 그대로). `rumor`·`explanation`·`record` 속 따옴표 문구는 참조 절 본문에 **포함**되어야 함.
   - 추가: `explanation` 의 인용은 **결과 화면에 실제로 보이는 본문**(`evidence` + `alsoShow`, `absent` 는 `scope`) 안에서도 찾을 수 있어야 한다. 아니면 플레이어가 해설의 인용을 화면 어디서도 확인할 수 없다.
3. **evidence ⊂ scope**: 정답 절이 조사 범위 밖이면 오류.
4. **hintOrder ⊂ scope**, `absent`면 `evidence` 비어 있어야 함, 그 외엔 1개 이상.
5. **answerCards** 가 모두 `cards`에 존재, 카드마다 최소 한 질문에 쓰이거나 `distractor: true` 명시.
6. **출력**: 오류 0이어야 `npm run build` 통과 (`prebuild`에 연결).

`npm test`(vitest): JSON 스키마, id 중복, chapter 해금 조건이 실제 건수보다 크지 않은지.

인간 검수: `flags: ['review']` 사건은 목회자 검토 후 플래그 제거. 플래그가 남아 있으면 게시판에 **표시되지 않는다**(빌드는 통과).

## 7. 화면

| 화면 | 경로 | 내용 |
|---|---|---|
| 위임장 | `/` (최초 1회) | 눅 1:1-4 전문 + 이름 입력 → 게시판. 이후엔 건너뜀 |
| 게시판 | `/board` | 사건철 탭 3개 + 증언대 탭. 쪽지 그리드. 상단에 조사관 이름·등급·해결 수 |
| 사건 파일 | `/case/:id` | 소문·출처·조사 범위. [조사 시작] |
| 조사 | `/case/:id/read` | 본문 리더(전령 reader 재사용). 절 탭 → 증거 표시. 하단 고정 바: 증거 n/3, [판정하기] |
| 판정 | 모달 | 4택 버튼. 판정 이름 아래 한 줄 정의 |
| 결과 | `/case/:id/result` | 인장("조사관 ○○○ 확인") → 근거 구절 전문 → 해설 → [보관소] [재조사] |
| 증언 사건 | `/witness/:id` | 좌: 카드 더미 / 우(모바일: 하단): 질문 슬롯. [본문 보기] 시트 |
| 보관소 | `/archive` | 서랍 뷰 + 필터. 맨 아래 **조사관 기록**(이름 바꾸기 · 기록 초기화) |
| 완주 | `/complete` | 전경 + 다시 볼 본문 3개 |

모바일 우선(청년부 폰). 드래그는 데스크톱만, 모바일은 카드 탭 → 슬롯 탭.

## 8. 기술

전령과 동일: Vite · React 19 · TypeScript · Zustand(persist → localStorage) · react-router · vitest · vite-plugin-pwa · Vercel.
공유 가능한 것은 **복사**한다(모노레포 안 만듦): 본문 JSON·빌드 스크립트·reader 컴포넌트·verify 골격.

스토어(`src/store/progress.ts`)
```ts
{
  investigator: { name: string }                       // 위임장 화면에서 입력(선택, 기본 "조사관")
  solved: Record<caseId, {
    verdictTries: number; evidenceTries: number        // 첫 해결 때 값, 이후 불변
    bestTries: number                                  // min(verdictTries+evidenceTries) across replays
    replays: number; solvedAt: string
  }>
  witnessSolved: Record<caseId, { tries: number; bestTries: number; replays: number; solvedAt: string }>
  version: 1
}
```
쓰기 액션: `setInvestigator`, `solveRumor`, `recordTry`, `solveWitness`, `replay`(bestTries·replays 갱신), `importState`, `reset`.

## 9. 콘텐츠 작성 규칙 (요약 — 상세는 exclusion-list §4, §5)

- `rumor`는 본문 표현을 최대한 살린다. 현대어로 바꿀 때 뜻이 더해지면 안 된다.
- `source`는 집단 일반화 금지. 본문에 주체가 없으면 "(후대 통념)" 또는 "(본문이 반박하는 가정)"으로.
- `explanation`은 본문이 말하는 것만. "학자들은…", "전승에 따르면…" 금지.
- 판정이 두 가지로 읽히면 사건을 쪼개거나 버린다(예: 눅 7:34 — "탐식" 부분만 왜곡으로 좁힘).
- 증언 카드는 한 카드에 한 인물의 한 발언. 절 경계에서 자른다.
